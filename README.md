# Voice → MIDI

Turn a sung melody into notes. Analyze an audio file or sing into the microphone; review and edit the transcription, then export MIDI, MusicXML, JSON and CSV. PDF export is optional. In the desktop app, **Export** opens a Save As dialog where you choose the filename and format; it remembers the last destination folder across launches. Live takes also retain their full audit archive in `prises_live/`.

The desktop app also includes a note finder: sing a note to identify it, or click a piano key to hear it. Its answer gathers the note name, the tuning needle and the mic's reception in one card, and the needle's scale is named (**♭ lower** / in tune / **higher ♯**) while the measured cents stay in the detail line. Confirmed notes are kept in its short history as playable chips, including repeated notes; a held note appears once, and clicking a chip — or pressing **Space** on it — hears that note again. The history uses the readings captured with each audio block, so a busy interface does not lose a note that was already confirmed. It tells you whether the sung note is in tune or off with a named verdict; a clear deviation includes its direction and measured cents, without guessing how you sang. The keyboard shows a range you choose — **Voice**, **Low voice** or **Whole keyboard** — so its keys stay readable, and it never recentres under your pointer. Its piano answers the keyboard too: Tab to it, choose a key with the arrows, press **Enter** to hear it.

## Install

Python 3.12 is recommended, on Windows, macOS or Linux.

```bash
# Windows
py -3.12 -m venv .venv
.venv\Scripts\activate

# macOS / Linux
python3.12 -m venv .venv
source .venv/bin/activate

pip install -e ".[dev]"
```

The rest of this file assumes the environment is activated: `python` and
`pytest` below are that interpreter (on Windows without activation, use
`.venv/Scripts/python.exe` instead).

## Use the app

A new live transcription stays in the results page until you export it. Re-singing a selected range updates the take: you audition the phrase, then keep it or cancel it (the original take is also kept if recording or re-analysis fails). Corrections, note moves and deletions are committed as one transaction: failed validation or derived-fact rebuilding leaves the displayed reading and undo/redo history untouched, while a successful edit publishes one new result and one whole-take undo state. Kept replacements join history only after you accept them. Note edits can be undone and redone; a manual pitch correction keeps the note timing and marks the audio-based coherence check as unavailable for that edited result.

```bash
v2m gui
```

When Windows records an audio effects chain for the chosen endpoint — the sound settings' **audio enhancements** — and that chain is not switched off, the home screen says so under the device name: such a capture is filtered by the driver before analysis, and nothing inside the take can reveal it. ## Web version

`web/` is a static page that runs the **live half** in the browser: pitch, notes, accents, the voice doubt, a piano roll and a MIDI export — plus **everything in one archive**: `prise.wav` (the recording), `notes.json` (every measurement with the settings behind it), `prise.mid` and a short notice, so a take can be re-analysed or compared later. The archive is compressed when the browser can deflate and stored when it cannot, so the download is smaller wherever possible and the file still opens everywhere. Its words sit in the markup as well as in `strings.json`, so the page reads before its script does — and it runs the same in Chrome and in Firefox — no server, nothing uploaded, nothing to install.

To look at it locally, serve the folder over HTTP (the page loads its strings from a file):

```bash
cd web
python -m http.server 8000
```

To publish it from GitHub: in **Settings → Pages**, set the source to **GitHub Actions**, then push to `main`. `.github/workflows/pages.yml` first replays the desktop's own segmentation cases against the JavaScript port and photographs the page at 1600 px with a demo take loaded — kept as the run's `wide-screenshot` artifact, and refused on the wide facts (the 1040 px measure, the notes table's flush-right numbers) so a wide-layout regression stops the deploy — measures the page in a browser at eight resolution classes — from a 320 px phone to a 2560 px screen, a phone held sideways included — where a sideways scroll, a lost measure, a masthead that eats a landscape phone or a control smaller than 24 px stops the deploy, audits both palettes in the three visible states at each of those classes with axe-core (48 audits: a violation or a rule axe could not decide fails the run), then deploys `web/`.

The notes can be auditioned in the page before exporting: it plays them through the **desktop's own piano** — the same additive model, with attacks and brightness following each note's accent, a damper on short notes, a pedal tail on held ones and a light room — so a take is judged by ear on the instrument it will be compared against. **Voice + piano** plays the take's own recording over those same notes, which is where a wrong note or a sagging pitch becomes obvious; the recording stays in the page and is never uploaded. While it plays, a playhead follows the roll, lights the matching row in the notes list and names the note being heard. A click in the roll hears the take from that second, in whichever mode was last chosen, and **Space** starts or stops it without reaching for the mouse. No microphone at hand? The **Demo take** button fills the page with a short sung phrase — a real signal, read by the same chain — and plays it voice + piano in a loop, so listening, the playhead and the balance can all be tried with one gesture; press it again to stop — a click in the roll starts the loop from that second instead of ending it. Its phrase contains one deliberately out-of-tune note, so all three intonation verdicts appear, and leans sharp throughout its low register, so the register line has a habit to name. The page's tutorial opens the same demo from its **first step**, so a newcomer who has just read “press Sing” can hear an example right there instead of hunting for the button below; the sheet closes on that click, which puts the reading it produces on screen. The same sheet prints: **Print the page**, under the steps, gives black on white whatever the screen theme, with the tutorial unfolded, the notes table and its intonation lines — and no control, since none of them works on paper. On a wide window the notes table's numeric columns — number, start, duration, cents — sit flush right, headers included, so a start time reads by its last digit.

The page wears the desktop's palette warmed for a small studio — and it has the desktop's two of them: the pill beside the language toggle in the masthead switches between the warm paper and the night-and-copper sheet, the choice is remembered for the next visit — under the desktop's own preference name and its same two words, `dark` and `light`, so the two agree on what a value means — and until you make one the page follows the system's light or dark preference. With a night masthead, cream paper, a hairline between sections and a single frame around the roll, whose black keys shade their lane and whose bars are solid copper under a copper playhead needle. Each note's distance from its key is in the table in signed cents, coloured by the desktop's own verdicts — in tune up to 10 cents, close up to 25, off beyond, with the word on hover — so the lit row answers "just or off, and by how much" while it sounds. A line under the table summarises the take — how many notes sat on their key, and the lean only when enough notes back it — names the register habits (low, mid, high) and the positional ones (a start or an end that leans while the whole take cancels out) that the take's own evidence supports. A clock under the roll gives the position and the total duration while it plays, and a slider sets the voice / piano balance as it plays — no restart, with a one-click reset to the reference — kept between visits, together with the page's language and the comparison you were listening to (a remembered voice + piano with no recording falls back to the piano), so the setting that suited your room is still there next time.

**What a file analysis computes here, and what it does not:** the page decodes the file at its own audio engine's rate (44.1 or 48 kHz, whatever the browser runs), reads the **first channel only** when the file has several, then re-reads a 23.22 ms window every 11.61 ms with the ported YIN. From it come the notes — start, duration, pitch, measured distance to the nearest semitone in signed cents, accent, voice doubt — the piano roll, the intonation summary (in-tune share, tendency, registers, start and end) and a type-0 MIDI file at 120 BPM. It computes **no tempo, no meter, no key, no chords, no rests, no position in the measure, no notation, no PDF**, and no note is snapped to a detected key. The desktop brings the same file to 22.05 kHz, reads it with pYIN over a 93 ms window, absorbs the global tuning offset before rounding, and draws all of that from it: that is why its notes can differ from the ones the page shows — a boundary the two windows do not date to the same millisecond, a note one dates and the other does not. Tempo, notation and the PDF stay in the desktop app because pYIN needs librosa, which does not run in a browser.

## Command line

```bash
v2m analyze chant.wav --quantize
v2m analyze chant.wav --pdf
v2m live
v2m --lang en analyze chant.wav
```

`analyze` accepts `--min-conf`, `--min-note`, `--transpose`, `--quantize`, `--pdf` and `-o`/`--output`. It writes MIDI, MusicXML, JSON and CSV; `--pdf` also writes a PDF when MuseScore or LilyPond is installed. A missing PDF tool skips only the PDF; a conversion failure exits with code 2. Held notes in MIDI share one channel-wide sustain pedal: overlapping or adjacent sustain windows are merged so an earlier note cannot lift the damper under a later one. `--lang fr` and `--lang en` select the interface language.

`serve` is the optional localhost companion: `v2m serve` listens on `127.0.0.1` only (never on the network) and answers four routes — `GET /health` (`app`, `api`, `version`, `features`), `POST /analyze` (audio bytes in, the same JSON payload the `.json` export carries out, written to no file), `POST /render` (a corrected note list with its tempo, meter and key, in the `/analyze` shapes; the MusicXML the desktop would engrave for those notes comes back as text, no file written) and `POST /compare` (an exported `notes.json` plus its take as base64 in the same JSON body: the desktop re-reads that audio and answers how the two readings differ — pairs, `stable`/`near`/`changed`/`missing`/`added` counts and the reason codes `pitch`, `attack`, `duration`). The GUI and `live` never start it: the web page calls it while it runs, because the browser cannot run pYIN. `--port` picks the port (default 8765); `--allow-origin` (repeatable) names a page origin allowed to call it — a page served from `localhost`/`127.0.0.1` and a non-browser client are always allowed, while a published GitHub Pages page must be named. Any other origin is refused without a CORS grant, errors come back as codes (`origin`, `audio`, `exported`, `incomplete`, `busy`, …), one analysis runs at a time, and a body over 60 MB is refused before it is read.

## Diagnostics

These tools are optional. Run them from the project root, inside the activated environment.

- Offline attack selection uses a vocal neighbourhood before or after a candidate, so an isolated non-vocal burst does not set the reference for soft articulations. Candidate selection precedes force normalization; the live detector and pitch gates are unchanged. Observation cache version 5 rebuilds older evidence automatically; saved exports are not rewritten. This does not certify note accuracy on unannotated recordings.
- `scripts/score_accuracy.py`: inspect a transcription. `--truth` compares known notes; `--json` writes a report; `--output` selects its artifact folder; `--no-attacks` omits attack evidence; `--compare` checks repeatability; `--golden` checks a saved reference; `--diagnose` shows which thresholds the take exercised.
- `scripts/profile_analysis.py`: measure analysis time. `--repeat` sets the number of runs; `--profile` adds a function profile; `--top` limits that table; `--json` writes measurements; `--output` selects the artifact folder; `--no-warmup` includes the first-run cost. The table ends with a `Rescue` line: the short-window sweep's own cost and how much audio it grafted into the pitch curve (0.0 when the gates refused everything).
- `scripts/confirm_s_sweep.py`: sweep the live note-confirmation threshold. `--values`, `--seeds` and `--amps` restrict the values, random seeds and test amplitudes.
- `scripts/liveseg_sweep.py`: sweep live segmentation. `--holds` and `--reartics` restrict the hold and re-articulation thresholds.
- `scripts/guide_capture.py`: record and annotate a checked take; `--audit` checks an existing take instead; `--annotate` writes a machine DRAFT of the notes for a recording made elsewhere (the audit and the corpus refuse it until an ear check turns it into a verified truth).
- `scripts/reinterpret.py`: reuse saved pitch evidence without decoding audio or running pYIN. `--save` saves evidence; `--observation` loads it; `--semitones`, `--min-conf` and `--min-note` change interpretation; `--sweep` and `--sweep-note` compare thresholds; `--against` compares evidence; `-o`/`--output` exports results.
- Breath annotations also work over digital silence: when the envelope's quiet floor is zero, a bump must reach the existing absolute RMS gate and retain the local peak/body contrast. Tiny fluctuations and constant hiss remain unmarked; note segmentation is unchanged.
- The live silence gate is one policy for the level you see and the reading: a capture block under the gate pushes unvoiced frames, so a periodic rumble far below the threshold can no longer confirm a note, while the soft voice that straddles the gate still reads every note.
- Live audio is downsampled to the analysis rate with a filtered conversion: energy above the target Nyquist no longer folds back into the audible band (measured 58 dB down on a 20 kHz tone), and the take's duration and clock hold at 44.1 and 48 kHz.
- Chord windows weight each note only by its sounding overlap with that window, not its whole duration. Chords remain harmonic hypotheses from the melody, not proof of an accompaniment.
- Intonation registers use three equal-width bands over the take's MIDI extent, not thirds of its note count. Repeated pitches stay in one band; a single-pitch take reports no register tendency. Each band still needs enough notes and a measurable mean deviation. Position splits the take's notes in note-count halves (start / end), never by the clock, so a slow note does not weigh more than a fast one and an odd count gives its extra note to the end; each half follows the same evidence rule, and a take that starts flat and ends sharp reads as a steady take plus two named halves.
- Missing-pitch rescue treats audible islands separately and leaves intervening silence unvoiced. Observation caches from earlier engine readings are rebuilt (format 4). Rearticulation boundaries are validated independently: a rejected candidate cannot cancel another justified cut.
- Phrase comparisons scale A's onsets to B's tempo before pairing and report residual shifts in B's seconds/beats. They do not automatically align phrase starts, so a real initial delay remains visible.
- The reading diff and the phrase comparison pair notes chronologically by dynamic programming with explicit costs (an association costs its onset shift, an unpaired note costs one beat), so a nearest-first choice can no longer leave a note missing while a complete pairing exists; an equal cost leaves the latest note unpaired, so the same two readings always pair the same way.
- MIDI exports release notes before restriking at a shared instant and transpose the key signature along with pitches (major/minor preserved). Double-dotted figure abbreviations use `N..` / `C..`, not repeated names.
- In live/final comparisons, a ±1-semitone difference is a rounding only within the take's onset tolerance; beyond that window it is a moved note. Existing saved comparisons are not rewritten.
- Live key snapping applies only to the newly closed note. Later key changes do not revise its published pitch label, deviation or snap displacement; final analysis remains a separate reading.
- Coherence suspects retain the pitch curve's original timestamps even when pitch frames are missing. A missing pitch interrupts a secondary plateau: separated fragments do not count as one continuous plateau.
- `scripts/coherence_summary.py`: summarize take audits by session; pass a takes folder to use a location other than `prises_live/`. `--lang` selects French or English labels.
- `scripts/replay_takes.py`: replay recorded takes at real time and save the live/final comparison. Replay delivers the entire file, drains and closes the last note before counting, and validates cached evidence and estimates tempo from the stopped capture at the analysis sample rate. Cancellation skips final analysis and archives no comparison; incomplete delivery times out as an error. `--out` selects a JSON report; `--take` selects one take; `--changed` replays only takes measured by an older engine (the fingerprint covers the replay's capture, segmentation, interpretation and comparison sources, and refuses to hash if a source is missing); `--root` selects the takes folder.
- A live/final comparison with an empty reading has no usable agreement rate: the GUI names the empty reading and the audit CLIs show `N/A`, not a reassuring 0%. Historical JSON `rate` fields stay unchanged; session and weekly means exclude these rates when the counts establish an empty reading. Exact counts remain included in mixed weeks; a week without any comparable rate has no trend point. Old journal final counts without provenance cannot establish emptiness.
- The weekly coherence trend copies live and final note totals from the take's `live_vs_final` block. A missing or older journal total without recorded provenance is shown as unknown (`-`), never estimated from the contour rate.
- `scripts/engine_drift_watch.py`: refresh outdated take comparisons. `--root` selects the takes folder; `--report` selects the Markdown report. Exits 1 if a reading changed. `--json` saves machine-readable results.
- `scripts/compare_takes.py`: compare two takes of one phrase. `--json` writes the comparison.
